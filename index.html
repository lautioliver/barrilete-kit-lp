agent-kit-template

Los agentes vuelan. Vos tenés la rienda.

Reglas, skills, docs y ADRs para que un agente lleve una idea del plan al PR, mientras vos aprobás el plan y mergeás.

Usar la plantilla Ver en GitHub
plan implement · review merge
La tesis

Dos decisiones son siempre tuyas.

Punto de control 1

Aprobar el plan.

/plan-feature investiga el código y los ADRs, arma la épica con sus issues y bloqueos, y te la muestra. No escribe código hasta que digas que sí.

Punto de control 2

Mergear.

/implement-issue llega hasta el PR con tests en verde. /review-pr lo revisa en otra sesión. El merge lo hace una persona.

Las skills mejoran con el uso, pero no se reescriben solas: /mejorar-skills propone ajustes en un PR y nunca afloja controles.

El flujo

De la idea al merge, con la rienda en dos nudos.

  1. 01
    idea
    /plan-feature
    épica + issues con bloqueos
  2. Punto de control
    02
    aprobás el plan
    Sin tu sí, no hay código.
  3. 03
    implementa
    /implement-issue <n>
    tests en rojo desde los criterios, código hasta verde, autorevisión, docs
  4. 04
    PR
    /review-pr <n>
    en otra sesión, más /security-review si toca rutas sensibles
  5. Punto de control
    05
    mergeás
    El merge lo hace una persona.
  6. 06
    retro
    en el issue fijado →
    /mejorar-skills
    propone ajustes en un PR

Si un issue depende de otro, queda con estado:bloqueado. El workflow desbloquear.yml le saca el label solo cuando se cierran todos los bloqueantes.

Skills

Pedilo en lenguaje natural.

/plan-feature
Investiga y convierte una idea en épica + issues. No escribe código.
crear-issue
Issues sueltos, auditorías a issues, bloqueos entre issues.
/implement-issue <n>
Del issue al PR con TDD. No mergea.
debug
Síntoma → evidencia → causa raíz → arreglo → test de regresión.
db-migration
Plan con compatibilidad, backfill y rollback antes de tocar el schema.
update-docs
Corrige los docs que quedaron viejos, en el mismo PR.
/review-pr <n>
Revisa reglas de negocio, ADRs, docs, tests y rutas sensibles. No aprueba.
/mejorar-skills
Junta retros y señales de CI y propone ajustes en un PR.
/estado
Resumen del proyecto y “¿qué puedo hacer ahora?”.
git-workflow
Ramas, commits y PRs.

Glosario

Diccionario de a bordo.

Las palabras técnicas de esta página, en una línea cada una.

Agente de código
Un modelo de IA (Claude Code, Cursor) que lee, escribe y ejecuta código en tu repo.
Plantilla de repo
Un repo de GitHub que se copia como punto de partida para uno nuevo, con todos sus archivos.
AGENTS.md
El archivo con las reglas que el agente lee antes de trabajar. CLAUDE.md y llms.txt apuntan a él.
Skill
Una receta escrita que el agente sigue para una tarea concreta. Las que empiezan con / se invocan como comando.
ADR
Architecture Decision Record: un documento corto que registra una decisión técnica, por qué se tomó y qué se descartó.
Issue
Una tarea, bug o pedido registrado en GitHub, con sus criterios de aceptación.
Épica
Un issue grande que agrupa varios sub-issues de la misma funcionalidad.
Bloqueo
Una dependencia entre issues: uno no se puede empezar hasta que se cierre el otro.
PR
Pull request: el pedido para sumar los cambios de una rama a la principal, donde se revisan.
Merge
Aceptar un PR e integrar sus cambios a la rama principal.
Label
Una etiqueta en issues y PRs (tipo:, estado:…) para clasificarlos y filtrarlos.
CI
Integración continua: checks automáticos que corren en cada PR y fallan si algo se rompió.
Workflow
Un archivo de GitHub Actions (.yml) que automatiza algo: correr tests, sincronizar labels, desbloquear issues.
TDD
Test-driven development: primero escribís el test que falla (rojo), después el código que lo hace pasar (verde).
Lint y typecheck
Revisiones automáticas de estilo y de tipos que encuentran errores sin ejecutar el código.
Test de regresión
Un test que reproduce un bug ya arreglado, para que no vuelva a aparecer.
Migración y schema
El schema es la estructura de la base de datos; una migración es el cambio versionado que la modifica.
Backfill y rollback
Backfill: completar datos existentes tras un cambio de schema. Rollback: el camino para deshacerlo.
Rutas sensibles
Partes del código donde un error cuesta caro (auth, pagos, schema, API pública) y piden revisión extra.
Retro
Notas de qué salió bien y qué no al cerrar un trabajo. Alimentan a /mejorar-skills.
gh y jq
gh es la CLI oficial de GitHub; jq procesa JSON desde la terminal.
